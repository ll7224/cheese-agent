# Cheese第一轮任务：在iPhone上记录真实的小猫

状态：Xcode26.6、首次启动状态、iPhoneOS SDK26.5及iOS26.5模拟器清单已核实；待落实独立App工作区后执行。构建与模拟器启动尚未验证。本文不授权调用付费模型、购买服务或发布应用。

## 目标

为主人开发一个原生iOS猫咪App的第一个可用版本：可以建立自家猫咪档案，从相册导入照片和短视频，添加日期和备注，按时间查看记录；关闭或重启App后记录仍然可用。

完整产品还将根据多日素材形成数字分身，并在手机关闭后持续发展虚拟生活。第一轮只交付记录能力，但设计不要把真实媒体和未来虚拟故事混成同一种事实记录。

## 产品与技术约束

- 原生Swift/SwiftUI，不使用Web/PWA或WebView套壳。
- 设计基线iOS17及以上；真机验收前核对实际系统，不擅自要求用户升级。
- 使用系统媒体选择器；照片和视频均需支持，视频须可播放。
- 持久保存档案、日期、备注及App管理的媒体文件。导入不能仅保存临时文件URL，也不能只靠相册引用假装完成本地持久化。
- 数据默认仅保存在App私有区域。第一轮不接云存储、AI生成、社区、账号注册或自动上传；不向外部服务发送猫咪素材。
- 在独立App工作区开发，不修改Cheese运行时及其他项目。可以使用标准Apple组件，不为第一轮搭建自定义框架。

## 必须走通的使用流程

1. 首次进入看到清晰空状态，建立一只猫的档案，填写名称并选择档案照片。
2. 从相册添加照片或短视频，输入记录日期和备注，保存后出现在时间线中。
3. 打开记录详情，照片方向正确，视频能播放，日期与备注正确。
4. 关闭并再次启动App，已有档案、记录和媒体仍可显示。
5. 删除一条记录，确认不再出现在时间线或详情中，且不误删仍被其他记录或档案引用的媒体。最后一个引用删除后清理对应的App内媒体，绝不删除系统相册原件。
6. 取消选择、导入失败或保存失败时，界面给出真实状态和可恢复入口，不显示假成功；大视频处理期间保持界面可操作，取消或失败不留下可见的损坏记录。

## 自行推进方式

先检查Xcode、可用iOS SDK及模拟器。环境缺失时给出准确阻塞并停止反复尝试，不自动安装Xcode、接受许可或操作Apple账户。

提出简短实现方案后按目标推进，自行组织文件与验证方式。把数据模型、媒体存储、界面职责适当分开，不把所有逻辑堆到单个视图文件。不要为了扩功能延后上述完整流程。

每次工作结束，在工作区保留一份简短进度记录：已完成事项、有效检查、明确失败或阻塞、下一步。后续新会话能根据该记录继续，不需要主人重述全部历史。不要将账号、签名凭据或模型密钥写进记录。
