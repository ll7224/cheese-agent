# 本机 Web 工作台

在仓库中执行 `npm run web`，打开终端给出的地址，默认是 `http://127.0.0.1:3210`。服务只监听本机；无需前端构建，也不会自动启动终端 REPL。

## 安装与启动

建议 Node.js 24 LTS、pnpm 10。仓库使用 `pnpm-lock.yaml`；SQLite 需要对应 Node ABI 的原生模块。已在独立临时目录验证以下流程：

```sh
pnpm install --frozen-lockfile --ignore-scripts
npm rebuild better-sqlite3
npm run build
npm run web
```

若没有可用 SQLite 预编译包，需本机编译工具链。`esbuild` 使用平台可选依赖提供的二进制；无需额外运行 `npm rebuild esbuild`。升级 Node 后重新构建 SQLite。

生产式启动：`node dist/index.js web`。运行时保留 `dist/`、`web/` 和 `node_modules/`。默认 CLI 为 `npm start`，初始化配置为 `npm run init`。

服务启动目录是公共配置来源，也是初始接入目录。要从其他目录启动编译版本，可先切换至该目录，再执行仓库中 `dist/index.js` 的绝对路径。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `CHEESE_PORT` | `3210` | HTTP 端口；`0` 使用系统分配端口 |
| `CHEESE_DATA_DIR` | `~/.cheese-agent` | 服务会话与事件数据 |
| `CHEESE_MAX_RUNS` | `3` | 主任务并发额度，正整数 |
| `CHEESE_MAX_CHILDREN` | `3` | 所有主任务共用的子 Agent 额度，正整数 |

## 目录、会话与配置

选择“接入本机文件夹”，输入已存在目录的绝对路径。符号链接按真实路径去重，不复制文件、不创建仓库。新会话固定属于所选目录；切换目录不迁移旧会话。消息支持 `⌘/Ctrl + Enter` 提交。

同目录多会话**共享实际文件**，可以同时运行。修改可能相互覆盖；没有自动合并、回滚或 worktree 隔离。目录是工具的工作位置，不是文件访问沙箱：有权限的工具仍可访问其他绝对路径。仅在信任本机用户和所配置工具的环境使用。

读取公共及目录中的 `cheese-agent.config.json`，兼容回退 `super-agent.config.json`。对象递归合并，数组整体替换，显式 `false` 生效；相对路径以声明文件所在目录解析。新会话固定有效参数，旧会话沿用保存版本；外部技能文件及项目文件不会冻结。

凭据保存为配置文件/环境变量引用，每次执行重新解析。撤销凭据后任务明确失败，不会静默换模型。会话及事件会隐藏敏感字段和已知配置密钥，包括分块文本中的完整密钥；这不是任意文件内容的通用秘密检测器。不要将未配置的秘密粘贴到任务或工具输出中。

只想离线体验，可在独立演示目录创建：

```json
{
  "model": { "provider": "mock", "name": "offline-demo" },
  "rag": { "enabled": false },
  "cron": { "enabled": false },
  "channels": { "feishu": { "enabled": false } }
}
```

Mock 只提供模拟文本，不代表真实模型的工具能力。`security.defaultRole` 支持 `owner`、`collaborator`、`guest`；保留旧默认值 `developer` 为 `owner` 的兼容别名。工作台没有配置管理后台。

## 调度、停止与恢复

超出主任务额度的任务 FIFO 排队；同一会话只允许一个未结束任务。子 Agent 使用独立全局额度，超额排队而不是丢弃。关闭页面或断开 SSE 不会停止任务。

“停止任务”只作用于该次任务及其子 Agent。停止期间显示“正在停止”，保留额度直至 worker 收敛。在 macOS/Linux 上，超时后终止该任务的进程组；不会按进程名清理其他会话。已经写入的文件、已经提交给外部系统的动作不撤销。

`Ctrl+C` 或 `SIGTERM` 关闭服务时收敛运行任务，未完成任务标为中断。下次进入旧会话可手动提交新消息，创建新的 Run；不会自动重放工具调用。刷新恢复会话路由、草稿及历史事件。

服务数据为 `state.json`，每次原子替换并保留上一版 `state.json.bak`。主快照损坏时尝试备份，并在终端提示；备份可能缺少最新事件。存储失败会停止新任务准入并取消运行任务，需要检查磁盘后重启。恢复前应保留原始文件。

同一数据目录只允许一个服务，由 `service.lock` 防止第二次启动误判活跃任务。正常退出自动释放锁。进程被强杀或机器断电后，为避免 PID 重用和并发抢锁，**确认原服务已经退出**，再删除该数据目录中的 `service.lock`；不要删除 `state.json`。重新启动后未完成任务收敛为中断。

## Channel 与 Cron

Web 服务根据启动目录的 `channels.feishu.enabled` 启用飞书。收到消息后进入同一个 Runtime，使用启动目录，会话按通道、聊天和发送者隔离。启用飞书意味着模型回复会通过该通道发送；测试使用本地替身，没有发送真实飞书消息。调试 Dashboard 也仅监听 loopback。

Cron 在服务启动时按已接入目录加载；新接入目录在首次创建会话时加载。`cron_manage` 通过 IPC 操作常驻服务，worker 退出不会丢失调度器。Cron 触发的 Agent 进入主任务队列；`run` 返回已提交而非等待嵌套任务占用同一额度。结果可在工作台或 Cron 日志查看。

不同目录应使用独立的 `cron.dataDir`；共享路径会被拒绝，避免同一任务被重复执行到不同项目。运行中的调度器配置修改在重启后生效；模型参数仍按每个会话固定。关闭当前任务不会删除它已经创建的未来定时任务，需要通过 Cron 工具显式禁用。周期任务重启后继续其正常调度，这与恢复旧 Run 的工具重放不同。

默认 CLI 模式的终端、Channel、Cron 也共用其进程内准入。分别启动 CLI 与 Web 属于两个独立服务，不提供跨进程额度协调；不要让两个服务管理同一 Cron 数据目录。

## 验证与限制

`npm test` 使用临时目录、可控模型和本机 HTTP 夹具，包含真实 worker、文件/shell、子 Agent、取消和恢复验证；需要允许 loopback 监听及创建子进程。真实模型单独验证，不作为测试套件的付费前提。结果见 [UI-10 验收记录](verification/local-agent-ui.md)。

当前快照在内存中保留完整历史，每条事件写入 JSON；适合本机小规模使用，尚未提供归档、数据库迁移或大历史性能保证。Windows 进程树清理、断电持久化的 fsync 保证、脱离进程组的后台进程不在本轮验证范围。此版本没有远程认证和多用户权限隔离。
