UI-01 → UI-02 → UI-03 / UI-04 → UI-05 → UI-06 → UI-07 → UI-08 → UI-09 → UI-10。

UI-03 与 UI-04 的需求依赖独立，可并行；实施时先固定共享的 Session / Run 契约，再约定文件修改范围。其他工单按依赖推进。UI-01 起即提供可用的简洁页面，UI-09 完成最终视觉与交互打磨。

## 全局完成规则

- 每项提交演示步骤、验证结果及尚存限制，不以“API 写完”或“页面静态完成”作为交付。
- 不同目录执行不得修改进程全局 cwd；同目录并发不得退化为整会话串行。
- 所有任务归属、配置版本、事件、取消均以稳定 ID 关联；不得解析 console 日志充当运行协议。
- 中间工单的能力边界要明确，UI-10 完成前不宣称整体可发布。
- 测试随行为引入；UI-10 是集成收口，不能把此前应有的隔离/取消验证全部推迟到最后。
- 技术选型在相应 Ticket 中记录简短决策；不为完成这些工单扩展成远程平台或通用 IDE。
