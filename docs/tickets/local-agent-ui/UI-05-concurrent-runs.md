# UI-05 — 多会话并发与主任务排队

类型：AFK · 状态：未开始 · 依赖：[UI-03](UI-03-session-config.md)、[UI-04](UI-04-execution-events.md)  
父级：[Spec](../../specs/2026-09-18-local-agent-ui.md) · 故事：US08、US09

## 要交付什么

同目录或不同目录的多个会话可同时工作，全服务主任务默认并发 3，超额 FIFO 排队。页面能看到每个会话的运行/排队状态、服务占用，以及同目录其他运行会话提示。

运行状态、消息、循环检测历史、重试状态、配置与工具可变状态按会话/Run 隔离。CLI、Channel 及随服务启用的 Cron 执行同样经统一准入，不能绕过额度。

## 验收条件

- [ ] 四个会话同时提交时最多三个主任务运行，第四个排队；任务完成/失败后额度释放并推进队列。
- [ ] 同目录两个会话能真正重叠执行并共享文件，不用整会话目录锁串行化。
- [ ] 页面显示同目录并发提示，不阻止提交，不自动合并或回滚修改。
- [ ] 同会话 queued/running/stopping 期间禁止第二次提交，后端也拒绝冲突请求；不同会话不受限。
- [ ] 多请求竞争下准入与额度计数原子一致；重复幂等键不重复排队。
- [ ] 一个任务的循环检测 reset、失败和配置变化不改变其他任务；跨会话不串事件或消息。
- [ ] 并发额度从服务配置读取，页面显示真实占用；完成父任务前不得遗留失去归属的执行。

## 验证与演示

用可控阻塞工具同时启动同目录两会话和异目录会话，证明执行时间重叠；并发提交第四项、释放一项观察推进。补充公共状态污染及完成/失败竞争的行为验证。
