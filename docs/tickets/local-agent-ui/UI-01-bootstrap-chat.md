# UI-01 — CLI 启动与首个对话闭环

类型：AFK · 状态：未开始 · 依赖：无  
父级：[Spec](../../specs/2026-09-18-local-agent-ui.md) · 故事：US01、US05、US16

## 要交付什么

通过显式 CLI Web 启动入口，在本机打开简洁首页，在启动目录创建会话、发送任务、查看最终结果并追问。提取共享运行服务，让 Web、现有 CLI 与 Channel 通过适配器调用，避免导入模块即启动 REPL 或以抓取 stdout 实现 UI。

首个切片就建立 Workspace / Session / Run 的稳定 ID 和持久化基础；可暂时仅开放启动目录与单任务。复用既有 Agent 引擎与工具，不另建一套推理流程。明确 UI 构建、生产资源提供和 CLI 启动命令，记录选型。服务只监听 loopback，同源提供页面与 API。

## 验收条件

- [ ] CLI 能启动 Web 模式并输出实际 URL，端口占用错误明确，Web 模式不启动交互式 REPL。
- [ ] 页面可创建会话、提交消息、展示最终结果和失败，再次追问使用同一会话上下文。
- [ ] Session / Run 落盘，重复提交相同幂等键只创建一个任务；其他浏览器访问不启动另一个运行服务。
- [ ] Web 关闭后已接收任务仍在服务中执行；本 Ticket 不宣称完成断线回放。
- [ ] 默认 CLI 交互、init 与 Channel 最终回复路径保持兼容，经同一运行服务执行。
- [ ] 新接口不返回服务密钥，写请求来源校验生效；普通文本不作为 HTML 执行。

## 验证与演示

用可控模型及临时目录演示提交、追问、错误和重复请求；验证 CLI 与 Channel 适配器最终输出。建立后续 Tickets 所需的最小行为测试入口，不扩展无关测试体系。

## 边界

暂不提供多目录选择、并发调度、停止或完整动效。这里只交付真实最小闭环；后续契约不可通过本地假数据代替。
