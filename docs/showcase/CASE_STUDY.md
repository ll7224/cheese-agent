# 第一份任务样本：cmdk 禁用项导致末项导航失效

选择 **React + TypeScript 命令菜单组件 cmdk** 的历史真实缺陷：列表含禁用项时，`⌘+↓` 无法选中最后一个可用项。它是第一道开发样例，先验证 Cheese 能否完成定位、修改和测试，不作为完整求职作品或知识增强收益的唯一证据。

## 为什么选它

- 行为直观：键盘应从 `First` 跳到 `Last`，却停在原处，适合展示前后对照。
- 有真实来源：[上游 PR #47](https://github.com/dip/cmdk/pull/47) 已于 2022-09-05 合并，不需要人为发明缺陷。
- 范围可控：最终库修复是一行，已有 9 项键盘测试可以同时检测问题和相关回归。
- 有设计语境：上游 `ARCHITECTURE.md` 明确以 DOM 顺序决定选中项，而不是维护另一套 React 子元素索引。适合检验 Agent 是否尊重现有约定。
- 不需要账号、业务后台、真实用户数据或付费模型来校准样本。

## 2026-10-16 本机结果

| 候选 | 构建 | 固定键盘测试 | 观察 |
| --- | --- | --- | --- |
| 原始实现 + 禁用项 fixture | 通过 | 上游测试及外置裁判均为 6 通过，3 失败 | 三种跳到末项的快捷键都仍选中 `first`，期望为 `last` |
| 相同输入 + 上游最终一行修复 | 通过 | 上游测试一次 9/9；外置裁判 8/9，页面加载超时项单独重跑通过 | 三种末项快捷键恢复；外置裁判累计 9 个不同测试通过，无剩余失败 |

缺陷失败分别对应 Meta+ArrowDown、Meta+Control+j、Meta+Control+n。外置裁判第一次参考运行中的 Alt+Control+n/p 用例在 `beforeEach` 页面加载阶段超时；保持代码和断言不变，只重跑该项后通过，首次失败也保留在报告中。完整输出及截图保存在[样本证据目录](../../eval/evidence/cmdk-disabled-last/)。本节是样本和裁判的校准结果；实际 Agent 尝试见下节。

实际环境：macOS 26.5、Node 16.20.2、pnpm 7.9.0、Playwright 1.24.1、Chrome 155.0.8059.82；Next 12.1.6 / React 18.2.0。历史 WebKit 在该主机打开页面失败，验收使用显式 Chrome 配置；相关测试断言和库实现未为浏览器适配而修改。

## 首次实际尝试：补丁有效，运行没有正常交付

2026-10-17 复核现存会话与候选文件，结果如下：

- 第一次运行只留下工具调用，没有最终答复，却被旧循环标为 `completed`。当时未记录确切停止原因，不能反推成预算耗尽。
- 用户追问中断原因后，第二次运行在第 4 步通过 `edit_file` 完成一行修复：末项索引改用可选 DOM 项数量，而不是包含禁用项的过滤计数。该修改由 Cheese 产生，主持人没有代改库源码。
- 第二次运行仍继续执行多组检查，到第 14 步累计输入 521,097、输出 9,681，共 530,778 Token，超过 500,000 预算后失败，未返回交付摘要。原会话保留失败状态，不将它改写为自主成功。
- 主持人随后提供中立 Chrome 入口并独立验收：候选构建通过、原有键盘测试 9/9、固定外置裁判 9/9。逐文件与固定源码归档比较，仅有这一行库修复与先前准备的禁用项页面 fixture 不同；测试断言、依赖和构建配置未变。验收在现存工作副本执行，没有另建干净裁判副本。

补丁与构建/裁判输出见[候选结果](../../eval/evidence/cmdk-disabled-last/candidate-result.json)。这是**有人工追问及验收辅助的有效补丁**；自主执行到结果交付的闭环仍需后续新任务验证。本轮故障排查没有重新请求真实模型。

本次修正集中在已暴露的问题：预算、步数、循环熔断及空答复必须显式报未完成；worker 出错时保留完成的工具消息；Web 对话按运行显示失败/中断原因，历史无最终答复也显示提示。预算改为 `execution.tokenBudget`，全局仍默认 500,000，本样例目录为新会话配置 2,000,000。父子循环分别计量，不能当作整棵任务树的费用上限。

本机服务已安全重启。原会话经真实页面刷新检查，两次异常均显示在对话中，日志按钮可打开执行详情。预算相关的配置、累计计算、子任务继承、worker 持久化共 14 项针对性测试通过，Cheese 构建通过；本轮没有运行全量套件。

### 通过固定验收后，仍发现同名分组边界

候选用分组的公开值查找DOM，而有heading的两个分组可以同名；由heading推导的 `data-value` 不保证唯一。主持人新增一个独立诊断页：两个组均为 `Results`，项目匹配分数分别为0.2和0.8。候选不能把高分组移到首位，该用例失败；原先采用独立内部DOM标识的参考副本通过同一用例。

这个诊断不加入原来的冻结15项，也不改写本轮既定验收结果。结论是**固定任务与交付闭环通过，补丁保留一个已复现的边界缺陷**；不能沿用最终答复的“无未完成事项”作为全面正确的结论。下一次最小改进应处理分组内部身份与公开显示值的区分，保留15项并增加这一项回归。候选源码保持原样，未由主持人代修。

已准备独立的[FOLLOWUP.md](../../eval/cases/cmdk-group-ranking/FOLLOWUP.md)和16项执行入口，在候选副本添加同名分组页面及测试，不改其库源码。用户随后实际沿用原会话执行，run `2d06fca8-0a00-4ec3-bb3a-e8d0f42cccba`在30步停止，累计1,543,732 Token。新增断言两次失败后持续检索，没有源码写入、构建或最终16项验收。该轮是人工反馈后的失败迭代，不改写首轮15项通过的记录。

本地排查确认：bash失败结果只选stderr，漏掉stdout里的真实断言；grep搜入`.next`二进制缓存，污染并可能挤掉源码匹配；重放实际30次工具调用，没有触发基于精确参数重复的现有检测。旧会话还带入了上一轮历史，首步输入已40,052 Token。优先修Cheese工具结果，再新会话重试，不先调大上限。详见[排查记录](../../eval/evidence/cmdk-group-ranking/followup-diagnosis.md)。本次诊断没有修改候选源码，也未追加模型请求。

用户授权后已修复Cheese工具：bash失败输出同时保留两路，grep排除构建缓存与二进制；新增只读返回重复证据的提醒，并在完整工具消息后注入。18项相关回归、1项真实worker集成及构建通过；最终并行检查的一次Node测试进程通信异常，补跑受影响3项后通过。原轨迹回放第17步可提醒。工具修复阶段未代改cmdk候选；后续用户新会话的结果见下节，原15项验收及失败记录保持原结论。
